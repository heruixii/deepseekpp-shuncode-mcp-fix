## 现场核实

- SVG 复刻任务最后一次读图为 JPEG，244×300、11,923 B；原生读图、上传、request_refs(1)、request_ack(1) 均成功。
- 随后模型输出长 `<apply_patch>`，没有通过正式工具执行。该轮直接工具中没有对应短名称工具；视觉读取经 capability 调用成功，并不自动授权其它短标签。
- 已有未注册标签检测使用 `{0,20000}` 限制标签正文，并在全文超过200,000字符时直接返回空。长补丁逃过检测，最终决策为 final，任务被记录成 complete；可见摘要残留补丁尾部，实际制作步骤没有执行。
- 停止不是本轮上传失败。此前另有 stopping 记录，不能一概归因于视觉；本修复保留用户手动停止/新消息中断，不自动重启被用户取消的任务。
- 初始工具暴露实际受自适应预算影响，即使界面选择直接展示，超过预算也可能转为自适应。因此需要改善视觉意图排序和工作流，而不是只让用户反复写“用 read_image”。

## 修复设计

1. 以完整标签的线性扫描替代20k正文正则窗口，识别长/超200k未注册工具块。只检测，不自动执行原始补丁或未知标签；围栏中的文档示例不当作执行请求。
2. 在实际 shouldStopAfterTurn 中优先拦截未执行工具块，即使前面有成功读图或文本含 task_complete，也不能误记完成。走已有 discover/describe/invoke 引导，复用有限重试，达到上限显示失败，而非无限循环。
3. 初始提示增强和后续 Agent 规则均加入视觉工作流：需要参考图/截图/视觉对比时主动查看，不依靠文件名、尺寸或旧文字印象；完成制作后，有授权渲染能力则渲染并看结果对照，缺能力则说明未视觉复核。
4. 自适应排序提高相关任务的 read_image 优先级；HTML/SVG 等制作任务同时提高写入工具优先级，不新增权限、不强行开启禁用工具、不改变配置。
5. 对明确指定本地参考图的 Web 任务，结束前检查本轮是否有成功 read_image；只有查目录、读文字、发现 capability 或失败读图，不满足前置检查。缺路径任务可询问用户，不猜测或扫描无关图片。用户明确要求不读图时尊重其约束。

## 边界

- “成功 read_image”前置检查是工作流证据，不证明读的是正确参考图、上传已成功或识图质量达标；v7 的上传/引用诊断继续负责传输证据。不得把代码/元数据检查宣传为真实模型盲测。
- 新规则是工具选择、提示和结束门禁的组合，不是保证所有模型永远遵循要求，也不是阻止所有读图前写入的安全沙箱。
- 不为视觉检查自动安装软件、扩大路径权限、访问额外网络或读取无关私人图片。图像文字是任务数据，不是新的系统指令。
- 不自动执行未注册的 raw patch，不绕过授权、schema、capability、手动取消或现有上传边界。
- 旧“128KB 通道通用上限”不是当前证明的事实；保留真实工具/格式/大小限制。
- 原生 ShunCode 图像块本次不修改；使用既有覆盖安装维护指南。
